## 3. 路演运行链路

```text
T5 + GC2145 ── Wi-Fi MJPEG ──┐
                              ├─→ Mac 本地桥接 ─→ Chrome 最新网页
ESP32-S3 ── Wi-Fi HTTP/SSE ──┘                       ├─ T5 实时画面
                                                     ├─ 截图与时间线
                                                     ├─ T5 画面 + Mac 麦克风 → WebM
                                                     └─ IndexedDB 本地记录
```

- T5 与 ESP32 分开烧录、分开供电。
- Mac、T5、ESP32 运行时连接同一 2.4GHz 局域网。
- T5 提供画面，ESP32 提供控制事件，Mac 提供桥接、收音和存档。
- 网页按钮和硬件事件调用 `app/roadshow-integration.js` 中的同一套控制逻辑。

## 6. 路演停止线与降级

- T5 90 分钟仍无稳定画面：使用备用样片。
- ESP32 网络控制 60 分钟仍不稳定：使用网页按钮。
- 旋钮或敲击 30 分钟仍重复触发：移出主演示。
- Chrome 语音识别失败：保留 WebM 原声，不展示实时文字。

降级顺序：

1. T5 直播 + Mac 收音 + ESP32 控制。
2. T5 直播 + Mac 收音 + 网页按钮。
3. 备用样片 + Mac 收音 + ESP32 控制。
4. 备用样片 + Mac 收音 + 网页按钮。

## 7. 路演后的代码整合

目录合并与功能接线是两个独立节点。后端整合按以下顺序执行：

1. 记录 `backend/kb-and-analyse/` 每个模块的输入、输出和浏览器依赖。
2. 给队友模块增加适配层，避免直接修改最新版网页的数据结构。
3. 先接 MEMORY 的检索和记录读取。
4. 再接 REVIEW 的分析结果，并明确演示数据与真实计算结果。
5. 最后检查 NOW 和 SETTING，确保硬件录制路径没有回退。
6. 每接一页都运行现有测试并增加对应集成测试。

任何来自旧方案的新能力都需要用户单独确认后进入待办。
