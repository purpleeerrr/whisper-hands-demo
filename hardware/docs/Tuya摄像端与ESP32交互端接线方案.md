# Tuya 摄像端与 ESP32-S3 交互端接线方案

更新：2026-08-15（已按 NICEMCU-T5-DEV V1.2 原理图复核）  
适用原型：絮手 Whisper Hands 桌面创作摄影机

主板一级资料先读：[`NICEMCU-T5-DEV_V1.2_主板事实表.md`](./NICEMCU-T5-DEV_V1.2_主板事实表.md)。本文件定义当前双板接线和路演链路；主板内部引脚、复用冲突和待验证能力以事实表为准。

## 1. 分工与边界

| 控制器 | 负责内容 | 当前连接方式 |
|---|---|---|
| NICEMCU-T5-DEV V1.2（原理图核心符号 `XH-WB5E`） | 当前主演示提供 OV2640 实时画面；板载麦克风、扬声器、屏幕、触摸和 TF 卡属于待验证升级能力 | 独立 USB 供电；通过 Wi-Fi 向 Mac 提供 MJPEG |
| ESP32-S3 N16R8 开发板 | 旋钮、敲击、APDS9960 手势传感器；把操作翻译成事件 | 独立 USB 供电；通过 Wi-Fi 向 Mac 上的本地桥接服务发送事件 |

两块板当前不直接接线，也不直接互发数据。Mac 作为中枢：T5 提供画面；ESP32-S3 把输入事件发给 Mac；网页在 Mac 上完成录像、截图、重点语音区间和最终存档。录像动作不会再转发给 T5 执行。

```text
旋钮／敲击／APDS9960
          ↓ GPIO / I²C
       ESP32-S3
          ↓ Wi-Fi：HTTP POST /api/hardware/event
Mac 本地桥接服务（同一局域网，使用 Mac 的局域网 IP，不能填 localhost）
       ├── SSE /api/hardware/events → 最新网页：执行四项功能
       └── HTTP 代理 /api/t5/stream ← T5：MJPEG 实时画面
```

浏览器、T5、ESP32-S3 和 Mac 要连到同一个 2.4GHz 局域网；手机热点也可以。ESP32-S3 的目标地址是 Mac 的局域网 IP：

```text
http://<Mac局域网IP>:4173/api/hardware/event
```

ESP32 不能填 `localhost`，因为它的 `localhost` 指向 ESP32 自己。桥接服务已经在 `server.mjs` 实现：HTTP 接收 ESP32 事件，SSE 推送网页事件，并代理 T5 的 `/stream` 与 `/snapshot`。

原理图显示 T5 的 `U0TXD/U0RXD` 已连接 CH340C USB-UART，当前承担烧录和日志。后续若要脱离 Mac，再评估第二串口、局域网直连或让 T5 统一接管交互；当前不要把 ESP32 直接接到这组日志串口。

### 1.1 T5 当前不要外接传感器

T5 的 GPIO 已被摄像头、TF 卡、LCD、触摸、RGB、LoRa 和传感器大量占用。当前旋钮、敲击和 APDS9960 全部接 ESP32。尤其注意：T5 的 GPIO18/19 同时连接 TF 卡 D2/D3 和板上两个 PWM 接口；当前 SDIO 初始化后不能再用作 PWM。

## 2. ESP32-S3 与传感器接线

ESP32-S3 的两个 `3V3` 针脚数量足够。只使用其中一组 `3V3 + GND` 接入面包板两条电源轨，再由电源轨分给三个模块。所有信号线从模块直接接回 ESP32-S3，初期均可使用杜邦线，不需要焊接。

### 2.1 先建立面包板电源轨

| 从哪里来 | 接到哪里 | 线色 | 作用 |
|---|---|---|---|
| ESP32-S3 `3V3` | 面包板红色 `+` 电源轨 | 红 | 为三个传感器提供 3.3V |
| ESP32-S3 `GND` | 面包板蓝色 `-` 电源轨 | 黑 | 三个传感器与 ESP32-S3 的共同参考地 |

若你的面包板长电源轨中间有断点，用一根红线连通两段 `+`，再用一根黑线连通两段 `-`。

### 2.2 每根线对应关系

| 模块 | 模块引脚 | 这一根线接到哪里 | 建议线色 | 用途 |
|---|---|---|---|---|
| 旋转编码器 VPAI-036（KY-040） | `+` | 面包板 `+` 电源轨 | 红 | 3.3V 供电 |
| 旋转编码器 VPAI-036（KY-040） | `GND` | 面包板 `-` 电源轨 | 黑 | 共地 |
| 旋转编码器 VPAI-036（KY-040） | `CLK` | ESP32-S3 `GPIO4` | 黄 | 旋转相位 A |
| 旋转编码器 VPAI-036（KY-040） | `DT` | ESP32-S3 `GPIO5` | 绿 | 旋转相位 B |
| 旋转编码器 VPAI-036（KY-040） | `SW` | ESP32-S3 `GPIO6` | 蓝 | 轴心按下按键 |
| 敲击传感器 VPAI-027（KY-031） | `+` | 面包板 `+` 电源轨 | 红 | 3.3V 供电 |
| 敲击传感器 VPAI-027（KY-031） | `-` / `GND` | 面包板 `-` 电源轨 | 黑 | 共地 |
| 敲击传感器 VPAI-027（KY-031） | `S` | ESP32-S3 `GPIO7` | 白 | 一次敲击输出一次短促脉冲 |
| APDS9960 STEMMA QT | `VIN` | 面包板 `+` 电源轨 | 黄（现有四芯线） | 3.3V 供电 |
| APDS9960 STEMMA QT | `GND` | 面包板 `-` 电源轨 | 绿（现有四芯线） | 共地 |
| APDS9960 STEMMA QT | `SDA` | ESP32-S3 `GPIO40` | 红（现有四芯线） | I²C 数据线 |
| APDS9960 STEMMA QT | `SCL` | ESP32-S3 `GPIO41` | 黑（现有四芯线） | I²C 时钟线 |
| APDS9960 STEMMA QT | `INT` | ESP32-S3 `GPIO10`，或悬空 | 灰 | 可选。初期用轮询读取手势时，不接这根线 |

```text
                 面包板 + 电源轨（红）
ESP32 3V3 ─────┬── KY-040 +
               ├── KY-031 +
               └── APDS9960 VIN

                 面包板 - 电源轨（黑）
ESP32 GND ─────┬── KY-040 GND
               ├── KY-031 GND
               └── APDS9960 GND

KY-040 CLK ───── ESP32 GPIO4       KY-040 DT ─── ESP32 GPIO5
KY-040 SW  ───── ESP32 GPIO6       KY-031 S  ─── ESP32 GPIO7
APDS SDA   ───── ESP32 GPIO40      APDS SCL  ─── ESP32 GPIO41
APDS INT   ───── ESP32 GPIO10（可选）
```

APDS9960 已接好的四芯线无需拆开、无需改色。程序中将 I²C 初始化写为 `SDA=40`、`SCL=41` 即可。

### 2.3 可编程 RGB 指示灯条（图中 10 颗灯）

从照片可见，这是一块带 `DATA` 标识的三线 RGB 灯条，外形符合 WS2812B 类可编程灯条。它可用作当前模式、录像、暂停、截图和语音观察段的状态提示。

| 灯条线/接口 | 应接到哪里 | 当前建议 | 原因 |
|---|---|---|---|
| `DATA` | ESP32-S3 `GPIO11` | 一根数据线 | ESP32-S3 用一个 GPIO 即可逐颗控制 10 个灯珠 |
| `GND` | ESP32-S3 `GND` | 共地，必接 | 数据信号需要共同参考地 |
| `POWER` / `VCC` | 5V 电源 | 暂不接 3V3 电源轨 | 10 颗 RGB 灯在高亮白色时电流较大，3.3V 轨不适合带它 |

**连接前核验：** 先看灯条背面或插头旁的丝印，确认三根线分别对应 `DATA / VCC / GND`。照片中的红、黑、黄三根线不能只靠颜色判断供电定义。确认后再接线。

### 灯条丝印字母对照：看到什么就接哪里

| 灯条上可能看到的字 | 它的中文意思 | 接到 ESP32-S3 的哪里 |
|---|---|---|
| `VCC`、`V+`、`5V`、`POWER` | 电源正极 | `5Vin`（ESP32-S3 由 USB-C 供电时取 USB 的 5V） |
| `GND`、`G`、`-` | 电源负极/地线 | 任意 `GND` |
| `DATA`、`DIN`、`DI`、`SIG` | 控制数据线 | `GPIO11` |

`POWER` 这类字表示“供电”，不是控制信号；`DATA` 才是由程序控制灯光颜色和闪烁方式的那根线。

**供电建议：** 无需额外购买电源。ESP32-S3 用 USB-C 供电时，灯条的 `VCC` 可接 ESP32-S3 的 `5Vin`，`GND` 与 ESP32-S3 共地。初期仅做状态灯效时，将亮度限制在 20% 以下；若出现亮度不稳定、ESP32 重启或颜色错误，再停用灯条并排查供电与数据线。

### 2.4 面包板与模块的物理摆放

```text
前面板一侧：  [旋钮 KY-040]              [APDS9960 感应窗口]
                     │                         │
                     └──────── 面包板 ─────────┘
                                      │
                                [ESP32-S3]
                                      │
                              [KY-031，贴外壳内壁]
```

- ESP32-S3 放在面包板中间或下侧，USB-C 朝外壳开口，便于烧录。
- KY-040 靠前面板，轴心穿出外壳；`CLK/DT/SW` 三根线同侧束在一起。
- APDS9960 放在靠近镜头的前面板，感应窗口朝用户手势区域，避免被金属或不透明材料遮挡。
- KY-031 用双面胶贴在用户会敲击的外壳内壁，便于后续调整位置与灵敏度。
- RGB 灯条放在前面板边缘或旋钮周围，作为可见的模式与工作状态提示；将三线插头留在可拔插的一侧。
- 红、黑电源线沿面包板边缘走；彩色信号线分别从模块直达 ESP32-S3。每根线两端贴标签，例如 `ROT-CLK G4`。

## 3. 输入与产品功能的映射

ESP32-S3 只输出清晰的事件，不处理录像文件和音频文件。

| 输入 | 建议职责 | 输出事件示例 |
|---|---|---|
| 旋钮旋转 | 选择四种功能 | `MODE:1` 到 `MODE:4` |
| 旋钮按下 | 执行当前选中的功能 | `VIDEO_TOGGLE`、`SNAPSHOT`、`AUDIO_MARK_START/STOP`、`VIDEO_FINISH` |
| 敲击传感器 | 备用快捷输入 | 初期仅启用：单击 `SNAPSHOT`、双击 `VIDEO_TOGGLE` |
| APDS9960 | 左右切换模式、靠近确认等低学习成本手势 | `GESTURE:LEFT`、`GESTURE:RIGHT`、`GESTURE:NEAR` |
| 摄像头视觉算法 | 识别 1–4 根手指及 3 秒倒计时 | 由 Tuya 摄像端或电脑视觉端处理 |

APDS9960 可可靠识别上下左右、靠近、远离等方向手势；它不适合承担“一根/两根/三根/四根手指”的识别。手指数功能留给摄像头视觉算法。

## 4. 建议调试顺序

### 阶段 A：ESP32-S3 单板输入验收（现在就能做）

1. ESP32-S3 单独 USB 供电；先不接 Tuya，也先不接 RGB 灯条。
2. 接旋钮后，在串口打印旋转方向、卡点和 `SW` 按下；旋转一格只产生一个 `MODE:n`，按下才产生功能事件。
3. 加入 KY-031，先只验证“敲一下串口有一个脉冲”，再启用单击／双击事件；误触发过多时关掉它。
4. 加入 APDS9960，先执行 I²C 扫描，再读左／右／近距离；手指数不在此模块测试范围内。
5. 最后接 RGB 灯条，亮度限制在 20% 以下，检查模式绿闪和红／黄／白／蓝状态灯。

### 阶段 B：ESP32-S3 → Mac Wi-Fi 事件验收

1. Mac、ESP32-S3 连同一个 Wi-Fi／手机热点；记录 Mac 的局域网 IP。
2. 启动本地桥接服务，让它先把收到的 JSON 原样打印到终端。
3. ESP32-S3 依次发送 `MODE:1`、`VIDEO_TOGGLE`、`SNAPSHOT`、`AUDIO_MARK_START`、`AUDIO_MARK_STOP`、`VIDEO_FINISH`。
4. 桥接服务通过 SSE 向网页推送同一事件；网页执行与页面按钮相同的录像、截图、语音区间或结束动作。
5. 每个事件连续发送 10 次，统计重复、丢失和延迟。

### 阶段 C：NICEMCU-T5-DEV V1.2 单板能力验收

1. 用 TuyaTool 手动烧录 `firmware/t5-camera/bin/WhisperHands_T5_camera_QIO_1.0.0.bin`。
2. 用 `460800` 打开串口，保存从上电开始的完整日志；重点看 audio、display、touch、camera、SDIO 的注册结果。
3. 从日志取得 T5 IP，在 Chrome 打开 `http://<T5-IP>/stream` 和 `http://<T5-IP>/snapshot`。
4. 连续出流 10 分钟。板载麦克风、屏幕、触摸和 TF 写卡分别建立后续测试，不与当前摄像验收混在一起。

### 阶段 D：全链路

T5 画面 → Mac 代理 → 网页 Canvas；ESP32-S3 输入 → Mac HTTP/SSE 桥接 → 网页执行四功能。任一板异常时，备用样片和网页按钮仍可完成演示。

需要脱离 Mac 时，再评估 T5 本地录音、TF 卡保存、屏幕/按键交互或局域网直连。这些能力已有板级电路基础，但尚未进入当前固件。

## 5. 现场注意事项

- 旋钮、敲击、手势模块均接 ESP32-S3，不占用 Tuya 的外设接口。
- 两块板各用 USB-C 供电；请勿把两个板的 5V 引脚直接相连。
- 当前不要连接两块板的 UART；T5 的 UART0 已用于 CH340C 烧录和日志。
- 固件和网站对事件名保持一致，先用串口日志核验，再接入真实录像控制。
