# 四功能软硬件联动 MVP 方案

> **这一版的决定：**用旋转编码器作为主控制器。旋转选择功能，按下执行；网页按钮始终可用。敲击传感器和 APDS9960 手势传感器各自作为可独立开启的实验入口，不影响主流程。
>
> **要跑通的四项功能：**① 开始/暂停录像；② 截图拍照；③ 开始/结束语音观察时间段；④ 结束本段录像。
>
> **范围边界：**本方案定义硬件输入、串口事件和验收方式。摄像头视频流、浏览器录制、语音转写与页面呈现由软件侧实现；硬件只向软件发送明确的操作意图。

## 1. 先看清本轮取舍

| 层级 | 入口 | 解决什么 | 本轮状态 | 为什么这样安排 |
|---|---|---|---|---|
| P0 | 旋转编码器 VPAI-036（KY-040） | 不看屏也能选择并执行四个功能 | 必做 | 操作可预期、接线少、一个器件覆盖「选择 + 确认」 |
| P0 | 网页/手机按钮、键盘 | 硬件未连上时继续完整演示 | 必做 | 为软件演示和现场排错保留退路 |
| P1 | 敲击传感器 VPAI-027（KY-031） | 手不方便按控制器时，用 1–4 下敲击快速触发 | 有时间再做 | 桌面震动容易误触发，需先测灵敏度和去抖 |
| P2 | APDS9960 STEMMA QT | 用挥手选择/执行，兼做接近、光线和 RGB 数据采集 | 有实物且 P0 稳定后再做 | 走 I2C，需确认开发板引脚、线材和模块实物 |
| P3 | 摄像头 + 视觉模型 | 识别一至四根手指并倒计时执行 | 本次不作为硬件 MVP 承诺 | 这是一条计算机视觉链路，需摄像头画面、模型、光线与误触发测试 |

### APDS9960 与「数手指」需要分开理解

APDS9960 是 I2C 光学传感器，可做接近、环境光、RGB 和方向手势识别。常见库直接提供上、下、左、右等挥手事件；它没有摄像头，也不输出「画面里有几根手指」。一到四根手指的识别要走摄像头和视觉算法，属于 P3。

参考：[Broadcom APDS-9960 产品说明](https://www.broadcom.com/products/optical-sensors/integrated-ambient-light-and-proximity-sensors/apds-9960)、[Adafruit STEMMA QT 手势示例](https://learn.adafruit.com/adafruit-apds9960-breakout?view=all)。

## 2. 用户实际怎么操作

### 主路径：旋转编码器

```text
旋转经过一个物理卡点 → 当前模式在 1/2/3/4 间切换 → 绿色模式预览，不执行功能
按下编码器轴心 → 板子发出当前模式的串口事件 → 执行灯效替代预览灯效
```

| 模式 | 旋转停下后的预览文案 | 编码器按下后的动作 | 硬件发出的事件 | 软件状态 |
|---|---|---|---|---|
| 1 | 录像：开始 / 暂停 | 第一次开始，第二次暂停 | `VIDEO_TOGGLE` | 待软件接入 |
| 2 | 留一刻：截图 | 截取当前画面/拍照 | `SNAPSHOT` | `MARK` 已能截图；需兼容新别名 |
| 3 | 观察：开始 / 结束 | 第一次开始语音时间段，第二次结束 | `AUDIO_MARK_START` / `AUDIO_MARK_STOP` | 待软件接入 |
| 4 | 结束本段录像 | 停止并结束当前录像段 | `VIDEO_FINISH` | 待软件接入 |

**模式 3 是时间段标记，不启动第二份音频录制。**模式 1 开始录像时，视频原始音轨同步开始采集。模式 3 的第一次点击只把此刻记为「语音观察开始时间」；第二次点击记为「结束时间」。软件在录像结束后，根据两个时间点从原始音轨取出该段，再转写和整理。这样一块麦克风只服务一条原始音轨，录像状态与观察状态也能同时存在。

### 旋转只预览模式；点击才执行

不以「转了多少度」作为规则。KY-040 这类编码器有连续的物理卡点，固件每识别到一个完整卡点就切换一次模式。顺时针 +1，逆时针 -1，超过 4 后回到 1。一个完整卡点的 A/B 相位变化才算有效，半格抖动不切换。

| 阶段 | 触发 | 灯光 | 会不会发送媒体事件 | 结束条件 |
|---|---|---|---|---|
| 模式选择 | 旋转经过一个完整卡点 | 屏幕持续显示「已选择：1/2/3/4 + 功能名」；RGB 每 1.5 秒循环绿闪 1/2/3/4 下，对应当前模式 | 不会；只发送可选的 `MODE:n` | 再次旋转切到新模式，或立即点击执行 |
| 功能执行 | 按下编码器轴心 | 按下方「点击之后」的执行灯效显示 | 会；发送当前模式的功能事件 | 由截图完成、录像状态、语音观察状态或结束录像决定 |

举例：你转到「3 观察」后，屏幕会持续写着「已选择：3 观察」，RGB 每 1.5 秒绿闪三下。此时还没有开始标记语音；只有按下旋钮，才会发出 `AUDIO_MARK_START` 或 `AUDIO_MARK_STOP`，选择显示结束，灯再变为蓝色或红色。

选择态优先显示「下一次点击会做什么」。屏幕右上角同时保留一个小型真实媒体状态点：红＝录像中、黄＝已暂停、蓝＝观察语音时间段已打开、灰＝待机。这样用户旋转时能同时看到“当前选中功能”和“录像实际状态”。RGB 灯用于显示选中功能；点击执行后恢复对应的红、黄、白、蓝执行灯效。

### 点击之后，指示灯只显示当前最需要被看见的状态

指示灯是操作反馈，不承担原始媒体记录。截图为瞬时动画；语音观察期间显示蓝色，结束后恢复录像/暂停的颜色。

| 触发后状态 | 灯效 | 含义 | 离开这个灯效的条件 |
|---|---|---|---|
| 录像进行中 | 🔴 红色常亮 | 视频与原始音轨正在记录 | 暂停、进入语音观察、结束录像 |
| 录像已暂停 | 🟡 黄色常亮 | 当前段保留，暂不写入新画面/音轨 | 恢复录像或结束录像 |
| 截图拍照动作 | ⚪ 白色闪烁 | 正在截取一帧画面 | 闪烁完成后恢复此前状态 |
| 语音观察时间段开启 | 🔵 蓝色常亮 | 原始视频音轨仍在记录；软件正在标记应被提取的语音区间 | 第二次点击模式 3、暂停或结束录像 |
| 待机 / 无有效操作 | ⚫ 灭灯 | 当前没有录像段，也没有语音观察区间 | 开始录像 |

> 语音观察仅在「录像进行中」时允许开启。录像暂停或已结束时收到 `AUDIO_MARK_START`，固件只提示一次短蜂鸣/灯闪，不发送事件。

### 备用路径：敲击与网页

| 入口 | 建议映射 | 启用条件 | 防误触措施 |
|---|---|---|---|
| 敲击传感器 | 1 下 `VIDEO_TOGGLE`；2 下 `SNAPSHOT`；3 下切换 `AUDIO_MARK_START/STOP`；4 下 `VIDEO_FINISH` | 先用编码器切入「敲击控制已开启」状态 | 首次脉冲后 900 ms 内计数；80 ms 去抖；执行后冷却 1 秒；四下结束录像需二次提示音 |
| 摄像头视觉 | 1 / 2 / 3 / 4 根手指分别触发四项功能；每次识别先倒计时 3 秒 | 摄像头画面、手指数算法、倒计时取消机制均已单独验收 | 倒计时内手势消失或手指数变化则取消；P3，不进入当前硬件 MVP |
| APDS9960 | 左/右挥手切模式；接近（`NEAR`）执行当前模式 | 模块初始化、I2C 扫描通过、桌面光线实测稳定 | `FAR` 和无法识别的手势只忽略，不执行结束操作 |
| 网页/手机按钮 | 与四个事件一一对应 | 始终可用 | 页面显示当前录像/录音状态 |

> 敲击输入会受到桌面、支架和创作工具碰撞影响。P1 演示只在实测误触发可接受时打开；否则保留为「概念备用入口」，现场演示走编码器和网页按钮。

## 3. 已有/可领取物料与接线边界

| 物料 | 物料编号/信息 | 接口 | 本方案用途 | 是否 P0 必需 |
|---|---|---|---|---|
| Tuya NiCEMCU_T5_2.8ISP 开发板 | 现场主控，具体板型与引脚待实物核验 | USB 串口、GPIO、待确认 I2C | 跑固件并把事件送到电脑 | 是 |
| 旋转编码器 | `VPAI-036`，KY-040；无限旋转 + 轴心按键 | GPIO | 选择并执行四功能 | 是 |
| 面包板、杜邦线、USB-C 数据线 | 现场基础物料 | — | 临时接线、供电、烧录和串口 | 是 |
| RGB 灯/蜂鸣器/板载屏 | 以现场物料和官方示例为准 | GPIO/PWM/板载接口 | 告知当前模式和操作已收到 | 建议 |
| 敲击传感器 | `VPAI-027`，KY-031 | GPIO | P1 多击输入实验 | 否 |
| APDS9960 STEMMA QT | Proximity / Light / RGB / Gesture Sensor | I2C；可能需 STEMMA QT/Qwiic 线 | P2 挥手、接近和环境感知 | 否 |
| 摄像头 | 由软件/设备链路另定 | USB 或板载/网络 | P3 手指识别；视频实际采集 | 否 |

### 编码器接线（P0）

KY-040 常见引脚为 `CLK`、`DT`、`SW`、`+`、`GND`。各店丝印可能不同，以模块背面的标注为准。

```text
编码器 +     → 开发板 3.3V
编码器 GND   → 开发板 GND
编码器 CLK   → 一个可用 GPIO（固件记为 ENC_A）
编码器 DT    → 另一个可用 GPIO（固件记为 ENC_B）
编码器 SW    → 第三个可用 GPIO（固件记为 ENC_SW）
```

- GPIO 编号暂时用 `ENC_A / ENC_B / ENC_SW` 占位。拿到 T5 板后，先看丝印、原理图或 BSP 示例，再填入真实编号。
- `SW` 按键采用内部上拉：未按下为高电平，按下读到低电平。`CLK/DT` 的上拉方式以模块实测为准。
- **不要预先把 P18/P19/P31 视为确定可用引脚。**开发板版本、屏幕和外设占用会改变可用 GPIO。

### 敲击传感器接线（P1）

```text
KY-031 + / VCC → 开发板 3.3V
KY-031 - / GND → 开发板 GND
KY-031 S / DO  → 一个可用 GPIO（固件记为 KNOCK_IN）
```

- 先打印原始电平脉冲，手敲桌面、移动支架、放下工具各测 10 次，再决定阈值和计数窗口。
- 传感器输出的高/低有效逻辑以实际模块为准；程序必须可配置反相。

### APDS9960 接线（P2）

```text
APDS9960 VIN / 3V → 开发板 3.3V
APDS9960 GND     → 开发板 GND
APDS9960 SDA     → 开发板 I2C SDA
APDS9960 SCL     → 开发板 I2C SCL
APDS9960 INT     → 可选 GPIO（若固件采用中断）
```

- STEMMA QT 是 4 针 I2C 插头体系。若开发板没有对应插座，准备一条 **STEMMA QT/Qwiic 转 2.54 mm 杜邦线**，或在现场由技术指导协助转接。
- T5 的 I2C 信号以 **3.3V 逻辑**连接。APDS9960 供电也优先使用 3.3V；若具体 breakout 标注可接 5V，仍要按该模块说明确认，不能凭 5V 习惯接线。
- 先跑 I2C 扫描和官方手势例程；未识别到设备时，立刻退回编码器主路径。

## 4. 软硬件之间只传六种明确事件

硬件通过 USB 串口每行发送一条 ASCII 文本，建议波特率先统一为 `115200`，以软件和固件实测一致为准。

| 串口行 | 来自什么操作 | 网页应该做什么 | 当前状态 |
|---|---|---|---|
| `VIDEO_TOGGLE` | 模式 1 执行；敲击 1 下 | 根据当前录像状态开始或暂停 | 待软件接入 |
| `SNAPSHOT` | 模式 2 执行；敲击 2 下 | 截图/拍照，并写入一条事实记录 | 软件需兼容；当前 `MARK` 可临时替代 |
| `AUDIO_MARK_START` | 模式 3 第一次执行；敲击 3 下；三指手势确认 | 保存当前录像音轨的起点时间戳，进入语音观察状态 | 待软件接入 |
| `AUDIO_MARK_STOP` | 模式 3 第二次执行；敲击 3 下；三指手势确认 | 保存终点时间戳；把这段音轨送入后续转写/事实确认队列 | 待软件接入 |
| `VIDEO_FINISH` | 模式 4 执行；敲击 4 下 | 结束当前录像段，保存/结算该段状态 | 待软件接入 |
| `MODE:1` 至 `MODE:4` | 编码器转动 | 网页可选：同步高亮当前模式 | 建议接入 |

### 状态合同

| 已知状态 | 收到事件 | 系统结果 | 失败或重复时怎么处理 |
|---|---|---|---|
| 待机 | `VIDEO_TOGGLE` | 开始视频与原始音轨记录；红灯常亮 | 无摄像头/麦克风权限时网页提示并保持待机 |
| 录像中 | `VIDEO_TOGGLE` | 暂停视频与原始音轨；黄灯常亮 | 连续 300 ms 内重复事件忽略 |
| 录像中或暂停 | `SNAPSHOT` | 白灯闪烁，保存一张截图/照片，随后恢复此前灯效 | 无画面时提示「当前无可截图画面」 |
| 录像中，未标记观察 | `AUDIO_MARK_START` | 保存 `audio_mark_start_ms`；蓝灯常亮 | 没有活动录像段时忽略并提示 |
| 录像中，观察已标记 | `AUDIO_MARK_STOP` | 保存 `audio_mark_end_ms`；生成待提取音轨区间；红灯常亮 | 多余的结束事件忽略 |
| 录像中或已暂停 | `VIDEO_FINISH` | 若观察未闭合则自动以当前时间闭合；结束本段并灭灯 | 未在录像时仅提示，不创建空记录 |

## 5. 固件行为与最小伪代码

```text
mode = 1
video_state = IDLE                 # IDLE / RECORDING / PAUSED
audio_mark_open = false
selection_active = false

识别顺时针一个完整卡点：mode = mode % 4 + 1；selection_active = true；串口发 MODE:<mode>；更新屏幕；每 1.5 秒循环绿闪 mode 下
识别逆时针一个完整卡点：mode = (mode + 2) % 4 + 1；selection_active = true；串口发 MODE:<mode>；更新屏幕；每 1.5 秒循环绿闪 mode 下

编码器 SW 按下：
  停止绿色预览灯
  selection_active = false
  mode 1 → 发 VIDEO_TOGGLE
  mode 2 → 发 SNAPSHOT
  mode 3 且 video_state == RECORDING 且 audio_mark_open == false
         → 发 AUDIO_MARK_START；audio_mark_open = true；蓝灯常亮
  mode 3 且 video_state == RECORDING 且 audio_mark_open == true
         → 发 AUDIO_MARK_STOP；audio_mark_open = false；红灯常亮
  mode 4 → 发 VIDEO_FINISH
```

- 为每种输入做 50–100 ms 去抖，避免一次按下产生两条事件。
- 编码器 A/B 相位要按完整的顺时针/逆时针序列解码；不要以单个 GPIO 边沿或旋转角度直接换模式。
- 旋钮仍在转动时也可以点击；点击永远执行此刻已确认的 `mode`。绿色选择显示不会触发录像、截图或语音时间段标记。
- 固件在发出 `VIDEO_TOGGLE` 后立即切换本地灯效：待机/暂停转红灯，录像中转黄灯。网页若遇到权限或媒体错误，需在页面明确提示；硬件与网页状态回执留作下一轮协议扩展。
- `SNAPSHOT` 的白灯闪烁建议为 150–250 ms；结束后恢复红、黄、蓝或灭灯。
- 串口输出每次只发送一行，结尾带换行，例如 `SNAPSHOT\n`。
- 发生未知传感器值或 I2C 错误时，发送日志可带 `#` 前缀，例如 `# APDS_INIT_FAIL`；网页解析器忽略这类日志行。

## 6. 到现场的实施顺序

| 顺序 | 做什么 | 看见什么才算通过 | 失败时退路 |
|---|---|---|---|
| 0 | 核对 T5 具体板型、BSP、可用 GPIO、I2C、屏幕/LED/蜂鸣器占用 | 写入现场记录 | 请技术指导确认；不猜引脚 |
| 1 | 先完成 TuyaOpen 的 `switch_demo` 烧录与串口日志 | 电脑能烧录并看到串口输出 | 换数据线/端口，完成基础链路后再接传感器 |
| 2 | 只接编码器，打印 `CLK/DT/SW` 原始值 | 顺逆转各能稳定识别；按下/松开各一次 | 调换 `CLK/DT` 或调整上拉、去抖 |
| 3 | 写入四模式和六种事件 | 串口逐项发出准确文本 | 先用串口监视器验收，不急着连网页 |
| 4 | 网页接串口，逐项测试四功能 | 浏览器状态与硬件事件一致 | 网页按钮与键盘继续完成演示 |
| 5 | 加入敲击传感器并测误触发 | 10 次预设敲击中至少 9 次正确分类 | 关闭 P1，保留编码器 |
| 6 | 加入 APDS9960，先跑 I2C/手势例程 | 扫描到设备，左/右/接近各识别 5 次 | 关闭 P2，保留编码器 |
| 7 | 视时间评估摄像头手指识别 | 单独完成视觉验收 | 不与 P0 绑在一起 |

## 7. 验收清单

### P0：旋转编码器 + 网页

- [ ] USB 数据线、烧录和串口日志通过。
- [ ] 旋转一格只切换一个模式；顺逆方向正确。
- [ ] 每个完整卡点只切换一个模式；快速连续旋转不会产生半格重复切换。
