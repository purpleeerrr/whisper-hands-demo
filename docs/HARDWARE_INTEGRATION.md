# 硬件交互说明

## 整体路径

```text
AI Keyboard / ESP32 实体键
          ↓
 F8 / F9 键盘事件 或 USB 串口 MARK / VOICE_START / VOICE_STOP
          ↓
       浏览器 Demo
          ↓
 原始语音 + 转写 + 当前图片／视频 → 过程收件箱
```

网页短按按钮、F8 和串口 `MARK` 最终都调用同一个 `captureMoment()`。长按按钮、F9 和串口语音事件控制录音开始／结束。事件 ID 会去重，一次实体按压只产生一条收件箱记录。

## 路线 A：实体键发送 F8（赛前优先）

1. 在 AI Keyboard 固件中把短按键配置为 `F8`，把长按语音键配置为 `F9`；
2. USB 连接电脑，让 Demo 页面保持在前台；
3. 按 F8 留画面；按住 F9 开始录音，松开结束。声音暂由电脑／USB 麦克风采集。

这条路线不需要浏览器选择串口。它依赖 AI Keyboard 固件能编辑键值，具体 S1–S8 键位映射要在拿到厂商固件或引脚表后确定。

## 路线 B：USB 串口发送 MARK

1. 用 Chrome / Edge 打开 `http://127.0.0.1:4173/`；
2. 点击“连接设备”，在浏览器弹窗选择开发板串口；
3. 开发板以 `115200 baud` 发送一行 `MARK\n`；
4. 浏览器解析后触发“留一刻”。语音可另外发送 `VOICE_START\n` 和 `VOICE_STOP\n`。

最简单的固件输出：

```cpp
Serial.begin(115200);
// 按键被确认按下时：
Serial.println("MARK");
```

也可发送带唯一 ID 的 JSON 行：

```json
{"event_id":"evt_board_001","type":"MARK_PRESSED"}
```

## 当前验收状态

| 部分 | 状态 | 证据 |
|---|---|---|
| 网页“留一刻” | 已完成 | 可生成收件箱记录 |
| F8 键盘入口 | 已完成 | 浏览器监听 `keydown` |
| F9 长按语音入口 | 已完成 | `keydown` 开始、`keyup` 结束；原始录音与转写进入同一收件箱记录 |
| Web Serial 入口 | 已完成 | 支持 `MARK`、`VOICE_START`、`VOICE_STOP` 和 JSON 行，有自动化测试 |
| 电脑／USB 麦克风采集 | 代码完成，待用户授权验证 | 浏览器首次使用会请求麦克风权限 |
| AI Keyboard 板载麦克风 | 待验收 | 缺板载音频接口与固件确认 |
| AI Keyboard 键位固件 | 待验收 | 缺厂商固件／实际键位引脚表 |
| 实体键真机触发 | 待验收 | 需连上用户的板子连续测试 10 次 |
| 声光／触觉回执 | 待开发 | 需确认板子固件接口 |

## 真机验收标准

- 实体键连续按 10 次，每次只生成 1 条记录；
- 页面显示已连接或 F8 收到提示；
- 图片／视频已选择时，硬件按键能将媒体和文字一起收进收件箱；
- 长按语音后，同一条记录能播放原始录音并修改转写；
- 硬件断开时，网页按钮仍可继续演示。
