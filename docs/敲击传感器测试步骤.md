# 敲击传感器测试步骤（ESP32）

## 前提

- ESP32 已烧录 control 固件（DIO 版本）
- 敲击传感器接 ESP32 的 **GPIO 7**
- Mac 与 ESP32 连同一个 WiFi（现场 2.4GHz 热点）
- 桥接已启动（端口 8000）

## 0. 前置检查（每次开始先做）

### 0.1 确认 USB 线插好、板子上电

- ESP32 的 USB 线插到 Mac
- 板子上的 **电源 LED 常亮**（不亮 = 没上电，换线/换口）

### 0.2 确认串口设备出现

```bash
ls /dev/cu.usbmodem* /dev/cu.usbserial* 2>/dev/null
```

- 应看到类似 `/dev/cu.usbmodem1101`（ESP32 的名字）
- **没有任何输出** = 板子没插好 / 线是充电线不传数据 / 驱动没加载 → 先解决这个，别往下走

### 0.3 确认串口没被其他程序占用

```bash
lsof /dev/cu.usbmodem1101
```

- **有输出**（显示进程 PID）= 有程序占着串口（残留的 screen / pio / python）→ 杀掉：

  ```bash
  kill -9 <上面显示的 PID>
  ```

- **没输出** = 干净，可以继续

### 0.4 确认桥接在跑

```bash
curl -s http://127.0.0.1:8000/api/device/status
```

- 返回 JSON 且含 `"bridge":{"online":true}` = 桥接正常
- `Couldn't connect` = 桥接没起，先启动：

  ```bash
  cd <项目根目录>
  HOST=0.0.0.0 T5_BASE_URL=http://<T5的IP> node server.mjs
  ```

## 敲击次数 → 事件映射

| 敲击次数 | 事件 | 含义 |
|---|---|---|
| 1 次 | VIDEO_TOGGLE | 开始 / 暂停录像 |
| 2 次 | SNAPSHOT | 留一刻（截图） |
| 3 次 | AUDIO_MARK | 语音标记（开始/结束切换） |
| 4 次 | VIDEO_FINISH | 结束录像 |

## 操作步骤

### 1. 开串口监视

```bash
cd <项目根目录>
./.venv-platformio/bin/pio device monitor --port /dev/cu.usbmodem1101 --baud 115200
```

**先按 RST 或拔插 USB 冷启动**，应看到启动日志：

```
Whisper Hands ESP32-S3 control
我已开机
WIFI_CONFIG=READY
BRIDGE_CONFIG=READY
```

看到 `HEARTBEAT wifi=ONLINE ip=<热点分配的IP>` = 板子正常联网。

### 2. 确认 ESP32 知道桥接地址

在串口监视器里发送（直接打字 + 回车）：

```
HOST:<Mac局域网IP>:8000
```

应返回 `BRIDGE_HOST_SAVED host=<Mac局域网IP>:8000`。

### 3. 敲击传感器

- **敲 1 下** → 串口应出现：
  ```
  KNOCK count=1 waiting_for_group=true
  EVENT name=VIDEO_TOGGLE seq=N mode=1
  HTTP status=202
  ```
  （`HTTP status=202` = 事件已送到桥接；`status=-1` = 桥接没连上，回 0.4 检查）

- **快速连敲 2 下**（650ms 内，像鼠标双击）→ 应出现 `SNAPSHOT`

### 4. 验证网页反应

Chrome 打开 `http://127.0.0.1:8000/studio.html`，点「使用路演样片」，观察：
- 敲 1 下 → 状态 IDLE ↔ REC 切换
- 敲 2 下 → 时间线新增「留一刻」节点
- 敲 4 下 → 弹完成弹窗

## 当前已知问题

**只能识别 knock=1**：敲击传感器释放速度慢，`!previousKnockActive` 条件不满足，第 2 次敲击被过滤。

固件参数（`firmware/esp32-control/src/main.cpp`）：

```c
constexpr unsigned long kKnockDebounceMs = 70;   // 两次敲击最小间隔
constexpr unsigned long kKnockGroupMs = 650;     // 计数窗口
```

调试方向：
- 若传感器释放慢 → 加大 `kKnockGroupMs`（650 → 800~1000）
- 若双击太灵敏 → 减小 `kKnockDebounceMs`

## 串口命令兜底（传感器失灵时）

在串口监视器直接输入，效果等同敲击：

```
1     → VIDEO_TOGGLE（开始/暂停）
2     → SNAPSHOT（留一刻）
3     → AUDIO_MARK（语音标记）
3     → AUDIO_MARK（结束语音）
1     → 暂停
4     → VIDEO_FINISH（结束）
```

完整录制序列：`1 → 2 → 2 → 3 → 3 → 1 → 4`

## 排障速查

| 现象 | 原因 | 处理 |
|---|---|---|
| 串口监视没输出 | 板子没上电/线不对 | 0.1、0.2 |
| `port is busy` | 有程序占串口 | 0.3 杀掉占用进程 |
| `HTTP status=-1` | 桥接没起/地址错 | 0.4 检查桥接 + 重发 `HOST:` |
| 敲击没反应 | 传感器没接/接错脚 | 确认接 GPIO 7，敲 1 下看有无 `KNOCK` |
| 只识别 knock=1 | 传感器释放慢 | 调 `kKnockGroupMs` |
